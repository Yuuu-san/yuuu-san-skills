# 雨伞循环

在用户指定的范围内持续执行“独立复查 → 核实 → 修复 → 验证 → 再独立复查”。用户委托雨伞导航执行且导航选中本技能时，按本流程启动。其他排障、单次复查和讨论按各自请求执行。用户明确要求只读时，按圆桌的只读审查流程交付核实后的发现和验证缺口。

## 启动

读取相邻的 [雨伞圆桌](../yuuu-san-roundtable/SKILL.md)，按其规则组织独立成员、交叉核查和取证。依据用户目标确定审查范围和基线。**运行验收前逐项记录验收条件、必要检查及其用例和环境**，覆盖实现所依赖的路径和原始故障。基线检查发现的相关失败从第一轮开始跟踪。

有可执行的必要检查时，读[执行验收](references/executable-acceptance.md)，用已有等效入口或随技能提供的脚本固定清单并生成运行证据。人工验收也逐项保留经独立复查的证据。

## 每轮

1. 固定当前候选及其相对基线的实际差异，按圆桌规则分阶段派发。

   - 每位新安排的盲审者先只接收圆桌规定的原始材料。主持人收到该成员的必验清单后，再发待审对象、实际差异和验证记录。
   - 独立读稿的首轮材料按[文档审查](../yuuu-san-roundtable/references/document-review.md#独立读稿)派发。
   - 其余未参与实现的复查成员收到完整的约定范围、原始需求和实际差异。

   有上一轮修复时，在相应复查阶段提供修复证据。每轮独立复查都包含以下两项。单次复查按圆桌的讨论轮次收敛。

   - 对照原始需求和现行契约，审查约定范围内的当前实现，主动寻找此前遗漏的问题，包括本轮未改动的实现和业务路径。
   - 核对已有修复及回归证据，检查上一轮确认的问题是否解决，以及修复在受影响的路径上有没有引入新问题。首轮没有已有修复时，先记录原问题和关键验证条件。

2. 主持人逐项记录本轮发现、验证失败、跳过、未运行和历轮未结事项。在测试套件中定位到失败的子项，保留原始结果和所覆盖的验收行为。范围内或关联待核的事项一律保持未结。基线同样失败只证明失败已经存在，这类失败与新失败走同一修复流程。
3. 在授权范围内直接排查每项未结事项，核实后修复原因，包括实现、测试用例、夹具、运行环境和验证步骤的问题。修复后在拟交付候选上复跑原失败项和受影响的检查，验证原触发条件并记录通过证据。一项失败受阻时，继续处理其他可以独立完成的事项。
4. 修复后或候选有影响结果的变化时，固定新候选，从第 1 步继续。验证条件或支撑独立审查结论的证据实质变化时，复验受影响的检查并由独立成员复核更新的结论。按风险安排检查深度，仍适用于当前候选且无新疑点的证据可以复用。

## 完成条件与阻塞

宣告完成、标记任务完成或进入以本轮验收通过为前提的后续工作前，主持人须对照启动清单、各轮原始输出和独立复查结果，逐项确认最终候选的证据。没有结果记录的必验项按未通过处理。可执行检查须先核验最终候选的通过回执，再判断本轮是否满足全部完成条件。

- **通过**。问题的修复已在最终候选上验证，必要检查已实际通过。确需替代验证且用户与项目约定允许时，须由独立审查者核对原项的验收行为、触发条件和所需环境均得到覆盖，记录替代结果及原项实际状态。若原项自身的可用性属于交付要求，还须修复并复跑原项。
- **有依据排除**。用户明确将该项移出范围，或证据证明它在约定范围之外，且与必要验收无关。记录具体依据，交由独立审查者复核。基线复现、失败出在测试或环境、其他专项通过、检查事后改称可选，均不能单独作为排除依据。
- **未通过**。仍有失败、跳过、未运行、仅临时绕行、未查清归属或缺少验证证据的项，继续修复、补验或排查真实阻塞。

**只有全部事项均已通过或有依据排除、全部必要验收有通过证据，且同一最终候选完成「每轮」的两项独立复查并无新增确认问题，方可标记完成。** 单轮零新发现或某项修复通过时，仍逐项核对历轮遗留和必要检查。任何一项未通过，继续执行能推进它的下一步；偶发故障可按明确目标有界重复。

收到暂停或结束指令时按圆桌的停止规则执行，按实际状态汇报。达到用户约定的上限，或缺少必要权限、环境、证据或独立复查者时，先在剩余授权和资源内推进其他可完成的工作。确实无法继续时，以**未完成**汇报已做工作、未通过的验收项和恢复条件。若需扩大授权或确定尚未决定的产品取舍，只请求继续所需的最小决定。

交付时说明最终候选、轮数、已修复问题、必要验证结果、末轮两项复查的覆盖范围，以及排除依据和仍未通过的项。
