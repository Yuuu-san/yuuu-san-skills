# 雨伞循环

在用户指定的范围内持续执行“独立复查 → 核实 → 修复 → 验证 → 再独立复查”。普通排障、单次复查和讨论继续按各自请求执行。用户明确要求只读时，按圆桌的只读审查流程交付核实后的发现和验证缺口。

## 启动

读取相邻的 [雨伞圆桌](../yuuu-san-roundtable/SKILL.md)，按其规则组织独立成员、交叉核查和取证。确定审查范围、基线、验收条件和必要检查。有具体故障时，先按排障流程建立或核实能检出原故障的检查，再复查当前版本。其余任务按对象选择圆桌的相应审查流程。

## 每轮

1. 固定当前候选及其相对基线的实际差异。将完整的约定范围、原始需求和实际差异交给未参与实现的成员。每轮独立复查都包含以下两项，有上一轮修复时同时提供修复证据。圆桌的讨论轮次用于单次复查的收敛。

   - 对照原始需求和现行契约，审查约定范围内的当前实现，主动寻找此前遗漏的问题，包括本轮未改动的实现和业务路径。
   - 核对已有修复及回归证据，检查上一轮确认的问题是否解决，以及修复在受影响的路径上有没有引入新问题。首轮没有已有修复时，先记录原问题和关键验证条件。

2. 主持人用原始资料和可复核证据确认问题，继续核实影响验收的待核项。在授权范围内修复已确认的问题，逐项验证触发场景及受影响路径。在拟交付候选上完成必要检查。排障任务复验原始故障场景。
3. 修复后固定新候选，从第 1 步继续。候选或验证条件发生可能影响结果的变化时，同样重新复查并复验受影响的检查。按风险安排检查深度，仍适用于当前候选且无新疑点的证据可以复用。按用户约定的资源上限推进。

## 验收与结束

验收通过须同时满足以下条件。

- 对同一最终候选按「每轮」要求完成独立复查，两项检查均有与约定范围相符的证据。
- 最后一轮没有新增确认问题，范围内已确认的问题全部解决，也没有影响验收的待核项。
- 最终候选的全部必要检查通过。

收到暂停指令时按圆桌的停止规则执行。达到约定上限，或缺少必要权限、环境、证据或独立复查者时，完成其余可推进的已授权工作，记录未通过的验收项和恢复条件。交付时说明最终候选、轮数、已确认和已修复的问题、末轮两项复查的覆盖范围及必要验证结果。
