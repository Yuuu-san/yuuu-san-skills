# 雨伞导航

## 选出当前需要的技能

1. 从请求和当前对话确定交付物、现在做到哪一步，以及用户要的是选路、讨论、审查还是执行。`$yuuu-san-skill-router` 后面没有任务时，沿用对话里正在处理的明确任务。确实缺少任务时，只问一句目标是什么。
2. 以当前会话的技能清单、项目约定和可用工具为准。用户指定的技能优先。各技能的描述用来筛选，读最相关候选的 `SKILL.md` 核对触发条件、依赖、兼容性和副作用。Bug 排查、方向讨论和方案复查按[排障、讨论与审查分流](references/routing.md#需求排障和审查)选用主技能。其他技能有重叠或任务涉及多个阶段时，查[常见分流](references/routing.md)的相关小节。
3. 当前清单可能省略仅允许用户显式调用的技能。若需要核对，优先用环境提供的完整技能清单。也可按任务检查当前项目 `.agents/skills`、用户 `~/.agents/skills` 和 Codex 实际使用的技能目录，只读相关条目与调用策略。仅在磁盘找到的条目标明启用状态待核，排除已知禁用或不在当前作用域的技能。
4. 选覆盖当前任务所需的最少技能，主技能优先，辅助技能只在承担不同工作时加入。跨阶段任务说明在什么结果出来后才用下一项。没有合适技能时直接按任务处理。按用户的选择排除 `umbralla-flow` 与其 `hua-*` 技能。

## 给出建议或执行

- **只问怎么用时**，给出选中的 `$技能名`、各自用途和调用顺序。有必要时给一句可直接复制的调用示例。比较候选正文后说明取舍，到建议为止。
- **要交付具体任务时**，简短交代所选技能和分工，读取并应用当前可用且允许本次调用的技能，继续完成已授权的工作。仅允许显式调用的技能由用户点名触发。若用户尚未点名，仍用可用技能或通用方法推进，只有确需该专用流程时才请用户调用 `$技能名`。按实际执行情况说明哪些技能已使用、哪些仅为建议。
- **项目有既定流程时**，沿用项目已有的文档、验证入口和验收口径。写入、远程操作和委派限于用户授权范围。单个技能依赖缺失时，核实可用替代路径和交付缺口。
