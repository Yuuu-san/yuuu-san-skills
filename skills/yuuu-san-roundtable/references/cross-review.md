# 项目交叉审查与修复复验

## 确定审查对象

确认范围是单项改动、业务链还是全项目。记录实际目录、Git 根、分支、比较基线、项目规则及并行改动。工作区审查覆盖暂存、未暂存与范围内未跟踪文件。非 Git 资料用路径和版本标识，无需建仓。必要时保存脱敏差异。

## 覆盖与分工

按文件及关键业务路径记录负责人、已查内容、覆盖状态与缺口原因。每项标已查、部分、未查或明确跳过，重叠核查只计一次覆盖。

按[圆桌的首轮材料顺序](../SKILL.md#独立分析与交叉质疑)派发，确保盲审者先交清单。随后各席独立核查同一基线与实际差异。

- **规格。** 对照原始需求、现行契约、已确认决策和验收条件，查遗漏、越界及行为回归。缺规格时查已确认的预期，依据不足则待核。
- **工程规范。** 沿调用方和数据流检查异常边界、兼容性和维护风险。指出违反哪项项目约定或造成什么实际影响。
- **验证。** 按风险核对或独立复跑关键场景，覆盖改动涉及的金额、权限、状态机、重复请求或时间边界。主路径须有相应运行证据。

## 发现与核实

按[圆桌证据要求](../SKILL.md#证据与结果契约)记录发现，标明已做和未做的验证。主持人对照代码与业务规则合并同根因问题，保留各受影响路径，按影响排序。复现前核对连接目标和副作用，优先用隔离环境。静态证据已能确认的问题，仍标明运行验证缺口。

## 已授权修复

同一文件或紧密相关的改动指定一名负责人，保留并行工作。复用能检出原问题的用例，缺少时补最小回归检查。修复根因后复跑原问题及受影响路径，用基线区分原有与新增失败。

由非实现者对照原始问题、实际差异和验证结果复查。候选变化或有新发现时，定向复验受影响的结论。缺员按[圆桌规则](../SKILL.md#用户参与及失败处理)执行。

## 最终报告

分别回答规格是否满足、实现有何错误、验证覆盖到哪里。列出审查基线、已查路径、未覆盖项及原因。只审查时交付发现与修复建议，零发现也限定到已查范围。
