# 文档审查

用于核实执行方案、路书与规格，找出可能误导下一位执行者的错误。

1. 固定被审文件和版本。从用户原话、现行决策、契约、代码配置和实际验证记录中定位依据。先识别文档的读者和用途，检查仍有效的正文与历史记录各自的适用范围。
2. 让成员独立检查以下方面，按文档用途调整分工。

| 检查方面 | 到哪里核对 |
| --- | --- |
| 事实、范围和状态 | 关键术语、对象、路径、版本、进度及结论，与上述依据逐条对照。留意草案写成已决、计划写成完成、局部通过写成整体可用。 |
| 实施顺序和可行性 | 按步骤追踪前置条件、阻塞依赖、调用方、权限、迁移或回退，核对执行人按文档操作是否能到达目标。命令先静态核实入口与副作用，按授权决定是否运行。 |
| 验收和证据 | 核对每个主要目标是否有可观察结果，证据是否对应版本、环境和验收范围，失败、重试、边界或待验事项是否清楚。 |

3. 交叉检查高影响主张，主持人回到原文核实冲突。每项发现给出章节或行号、简短原文、相应依据、对实施或验收的影响，以及可直接采用的修改建议。按影响优先报告，区分可证错误、证据或信息缺口和有取舍的改进建议。
4. 大的方案问题给更优的实施顺序或替代方案，说明它如何解决原问题及新增代价。审查任务交付发现和改稿建议。获授权修改时更新业务单源，保留其他原文，核对受影响的交叉引用与验收表述。
