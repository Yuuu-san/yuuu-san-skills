# 文档审查

用于核实方案、路书、规格和交接文稿，找出可能误导下一位执行者的错误。只要求巡检文档和代码的差异时，按[文档与实现一致性](#文档与实现一致性)处理。

## 确定审查对象

固定文稿版本，明确读者、用途、适用阶段及范围。需要对照实现时同时固定代码与配置的版本。从用户原话、现行决策、契约和实际验证记录中定位依据，核对正文和历史记录各自适用的范围。

## 独立读稿

审查重要方案、路书、规格，以及跨人或跨会话的交接文稿时，在现有席位中安排一位未参加起草、未接触此前讨论和背景材料的成员，用新上下文复述。先看需求的盲审由另一位成员承担，两项可以并行。

1. **派发。** 使用不继承父会话历史的派发方式，核对实际参数或启动记录。首轮只给当前文稿及版本、审查范围、预期读者和复述任务。工作区、记忆和项目规则可能共享。
2. **先交复述。** 成员只读指定文稿，用自己的话分别说明文稿所述的现状、拟议变化和一条关键行为或执行路径。读交接稿时，第二项写接手人下一步要做什么。应由文稿交代却缺失的信息标为「稿内未说明」，指出位置和所缺信息，必要时注明应引用的依据。即使没有发现问题，也提交复述。
3. **核对首轮材料。** 主持人保留原始复述，对照实际派发内容和可取得的读取记录。发现首轮接触了额外背景时，在现有席位内换合格的新上下文重做。无法独立读稿或无法确认关键材料边界时，标为待完成，并按[缺员处理](../SKILL.md#用户参与及失败处理)继续其余核查。
4. **核对理解。** 对照文稿原句核对复述。对照原始需求和已确认决定核对正文。

   - **文稿缺口。** 关键规则缺失或有歧义。指出文稿位置和需要补充的规则。
   - **内容错误。** 正文与已确认要求或决定冲突。引用正文和对应依据。
   - **复述偏差。** 正文表达清楚，复述却与原句不符。引用接手人能看到的原句，必要时换新读者复验。
   - **待核。** 缺少判定依据时，记录具体待核项。

   获授权改稿时，在正文补足复述关键行为所需的最少规则，链接可读的正式依据供后续核实。

## 核对方案和实施计划

按文档用途分工。两部分同时在范围内时，分别给出结论。

| 检查方面 | 核对内容 |
| --- | --- |
| 方案 | 对照目标和现行契约，核对关键用户行为、适用范围、重要取舍及失败边界。指出仍需业务决策的事项及其后果。 |
| 实施计划 | 对照当前代码和配置核实入口、调用方、前置依赖、顺序、权限、迁移或回退，判断接手者能否按步骤到达目标。命令先静态核实入口与副作用，按授权决定是否运行。 |
| 事实和验收证据 | 核对状态、术语和各主要目标的可观察结果。区分草案、已决、已完成和部分验证。确认测试入口、验收条件及证据对应版本、环境和范围。检查失败、重试和待验事项。 |

## 记录和复查

- 交叉检查高影响主张。每项发现保留编号、章节或验收项、短原文、当前版本可核对的位置、依据、影响和改法。按影响分别说明确认的错误、证据或信息缺口和有取舍的建议。重大方案问题给出可行的替代方案或实施顺序，说明解决的问题和新增代价。
- 多轮复查时先重读最新文稿，按章节或验收项重新定位行号、页码或条款。章节移动或改名时以原问题的行为和影响范围核对归属。仍存在的问题按原编号保持未结，已关闭的问题再次出现时按原编号重开。保留历轮依据。
- 按授权更新业务单源，保护其他原文，复查整体目标、受影响的引用和验收表述。修改是为消除理解偏差时，用新上下文复述修订后的相关文稿，核对原缺口是否消除。仅审查时交付已核实的发现和建议。

## 文档与实现一致性

1. 按请求限定文档和代码范围，记录版本、文档生效状态及适用阶段。沿文档引用或搜索定位对应入口、字段、规则与配置，核对关键行为和边界。计划章节按约定的实施阶段判断。源码证据对应所查版本，部署或运行结论使用相应的实际证据。
2. 每项报告给出文档条款、代码或配置位置、版本、实际差异、影响和归属依据。核对现行裁决后，区分文档过时、实现与生效规格不符、尚未获批的草案和未到实施阶段的计划。以条款的生效状态和约定阶段为准，归属无法判定时保留缺口。零发现也说明核对范围。
3. 定向巡检只读交付结果及建议。文档与代码的修复分别按当次授权执行。
