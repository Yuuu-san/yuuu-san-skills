# 文档审查

用于核实执行方案、路书与规格，找出可能误导下一位执行者的错误。只要求巡检文档和代码的差异时，按[文档与实现一致性](#文档与实现一致性)处理。

## 确定审查对象

固定文稿版本，明确读者、用途、适用阶段及范围。需要对照实现时同时固定代码与配置的版本。从用户原话、现行决策、契约和实际验证记录中定位依据，核对正文和历史记录各自适用的范围。

## 独立读稿

对需要跨人或跨会话交接的路书、关键方案和规格，在现有席位中安排一位未参加起草、未接触此前讨论的成员，用新上下文复述。先看需求的盲审由另一位成员承担，两项可以并行。

1. 首轮只给当前文稿、适用的章节或版本、预期读者和复述任务。成员只读文稿，在接触背景资料、主持人解释和其他意见之前，先用自己的话说明文稿中的现状、拟议变化和一条关键行为或执行路径。能理解也应交复述。缺少依据时指出章节和读者必须掌握的具体信息，必要时指出文稿本应引用哪类来源。
2. 主持人保留原始复述，再用原始需求和已确认决定核对。读者无法还原或复述与已确认意图不同，且文稿没有说明清楚时，记录为文稿缺口。若文稿确有依据，引用接手者能看到的章节。获授权改稿时，把接手所需的规则写进文稿或链接到可读的正式依据。
3. 核对实际派发参数、成员返回的原始复述及可取得的读取记录。新上下文隔离的是对话，工作区、记忆和项目规则可能共享。发现额外背景进入首轮时，在现有席位内换新上下文重做。无法独立读稿或无法确认关键材料边界时，标为待完成，并沿用[缺员处理](../SKILL.md#用户参与及失败处理)继续其余核查。

## 核对方案和实施计划

按文档用途分工。两部分同时在范围内时，分别给出结论。

| 检查方面 | 核对内容 |
| --- | --- |
| 方案 | 对照目标和现行契约，核对关键用户行为、适用范围、重要取舍及失败边界。指出仍需业务决策的事项及其后果。 |
| 实施计划 | 对照当前代码和配置核实入口、调用方、前置依赖、顺序、权限、迁移或回退。命令先静态核实入口与副作用，按授权决定是否运行。 |
| 事实和验收证据 | 核对状态、术语和各主要目标的可观察结果，确认测试入口、验收条件及证据对应版本、环境和范围。检查失败、重试和待验事项。 |

## 记录和复查

- 交叉检查高影响主张。每项发现保留编号、章节或验收项、短原文、当前版本的行号、依据、影响和改法。按影响分别说明确认的错误、证据或信息缺口和有取舍的建议。
- 多轮复查时先重读最新文稿，按章节或验收项重新定位行号。章节移动或改名时以原问题的行为和影响范围核对归属。同一问题仍存在或再次出现时，沿原编号重新打开，保留历轮依据。
- 按授权更新业务单源，保护其他原文，复查整体目标、受影响的引用和验收表述。修改是为消除理解偏差时，用新上下文复述修订后的相关文稿，核对原缺口是否消除。仅审查时交付已核实的发现和建议。

## 文档与实现一致性

1. 按请求限定文档和代码范围，记录版本、文档生效状态及适用阶段。沿文档引用或搜索定位对应入口、字段、规则与配置，核对关键行为和边界。计划章节按约定的实施阶段判断。源码证据对应所查版本，部署或运行结论使用相应的实际证据。
2. 每项报告给出文档条款、代码或配置位置、版本、实际差异、影响和归属依据。核对现行裁决后说明是文档过时、实现与生效规格不符，还是尚未进入实施阶段。无法判定时保留缺口。零发现也说明核对范围。
3. 定向巡检只读交付结果及建议。文档与代码的修复分别按当次授权执行。
