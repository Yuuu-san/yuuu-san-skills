# yuuu-san-skills

Codex 全局协作规则与自创技能，用于版本管理、跨设备迁移及后续分享。

## 内容

- `codex/AGENTS.md`：全局协作规则。
- [雨伞圆桌](skills/yuuu-san-roundtable/SKILL.md)：多代理头脑风暴、交叉审查及配套参考文件。
- [雨伞Vtuber人设策划](skills/yuuu-san-vtuberPersona/SKILL.md)：虚拟主播的人物、声音方向、口头禅、分赛道内容与独立角色推演。

## 当前状态

本仓库从本机现用文件整理建立。全局规则已去除个人称呼和项目专用章节，保留初学者沟通偏好；圆桌技能和人设策划技能按各自完整目录收录。人设策划只包含可复用的方法与合成测试题，真实主播资料和个案记录留在各自工作目录。项目专用实现继续由对应项目维护。

仓库文件与本机现用文件是独立副本，编辑任一处不会自动同步另一处。

## 雨伞Vtuber人设策划怎么用

中文名为“雨伞Vtuber人设策划”，技能名为 `yuuu-san-vtuberPersona`，保留大写 `P`。它面向虚拟主播，支持完整人设策划、局部口头禅精修、内容样稿和根据试用反馈返修。

完整方案覆盖观看体验、主人设、身份/性格/能力/动机/禁忌、声音方向、主副赛道、口头禅候选、各采用赛道的具体示范、准备分工，以及“为什么做这个内容、怎样反应、观众记住什么”的三问。角色来历与动机由策划创作，真实经历、能力和意愿据实确认。

安装后可按以下方式发起任务。第一例是合成输入；实际使用时换成自己的已知材料，不必先编好完整人设。

**完整策划：**

```text
请用 $yuuu-san-vtuberPersona，为虚拟主播“纸灯”制作完整人设方案。
现有视觉是成年女性纸灯精灵，不改模型。她说话短而平稳，不爱互怼，
能画简笔小物，擅长慢慢改线。希望绘画为主、短RP为副。
请你设计来历、动机和人物特点，并写出各赛道可直接试做的具体内容。
目前没有音轨或真实观众数据，请明确候选与待核部分。
```

**局部修改：**

```text
请用 $yuuu-san-vtuberPersona，只修改我贴出的方案里的口头禅。
保留已有身份、视觉和主副赛道，给几组候选、跨场景例句和适用范围，
不替主播选定主次。以下是现有方案：……
```

**根据反馈返修：**

```text
请用 $yuuu-san-vtuberPersona，检查下面这段实际输出和反馈。
观众记住了素材笑点，但没记住人物特点。请定位具体断点、修改这段，
安排与改动相符的复验，保留旧观众的接触史。
原方案、实际输出和反馈如下：……
```

可以只安装人设策划技能，使用它不必同时安装全局规则或圆桌技能。独立主播/观众推演需要运行环境提供真实子代理能力；没有该能力时仍可完成设计稿，但须明确推演未执行，不能编写双方台词冒充验证。圆桌是独立的方案讨论/审查能力，不自动在每次人设任务中运行。Word等导出按需要使用相应文档工具；本技能不附带数据库账号、业务服务或自动导出程序。

希望改进技能时，可在 Issue 中提供去除个人信息的最小输入、实际输出和不满意的具体位置，并区分成品问题与方法问题。涉及真人的录音、私聊、身份映射或账号信息不直接公开。

## 换设备后安装

### 1. 获取仓库

新设备需要先安装 Codex 和 Git。本仓库公开，下载不需要登录 GitHub；向本仓库推送修改仍需要相应的写入权限及 GitHub 身份认证。

在准备存放仓库的目录打开终端，执行：

```sh
git clone https://github.com/Yuuu-san/yuuu-san-skills.git
cd yuuu-san-skills
```

需要从新设备推送更新时，可安装 GitHub CLI（`gh`），运行 `gh auth login` 和 `gh auth setup-git` 配置认证；也可以使用已经配置好的 SSH 或 Git 凭据管理器。

如果已经下载过仓库，在仓库目录执行：

```sh
git status --short
git pull --ff-only origin main
```

先确认 `git status --short` 没有输出；有本地改动时先处理，不继续拉取或覆盖。`--ff-only` 表示只接受可以直接向前更新的版本；如果失败，先核对分支和改动，不使用强制覆盖。

### 2. 确认安装位置

下表中的 `~` 表示当前用户的主目录。Windows 可在资源管理器地址栏输入 `%USERPROFILE%` 打开主目录；macOS 可在 Finder 的“前往文件夹”中输入路径。

| 仓库内的内容 | macOS / Linux 默认安装位置 | Windows 默认安装位置 |
| --- | --- | --- |
| `codex/AGENTS.md` 文件 | `~/.codex/AGENTS.md` | `%USERPROFILE%\.codex\AGENTS.md` |
| `skills/yuuu-san-roundtable/` 整个目录 | `~/.agents/skills/yuuu-san-roundtable/` | `%USERPROFILE%\.agents\skills\yuuu-san-roundtable\` |
| `skills/yuuu-san-vtuberPersona/` 整个目录 | `~/.agents/skills/yuuu-san-vtuberPersona/` | `%USERPROFILE%\.agents\skills\yuuu-san-vtuberPersona\` |

全局规则的位置以 Codex 实际使用的 `CODEX_HOME` 为准；未自定义时才使用上表的 `.codex`。如果该目录存在 `AGENTS.override.md`，Codex 会优先使用它；先核对其用途，不能仅复制 `AGENTS.md` 就认为规则已经生效。

新设备按上表安装所需技能。已有设备可能仍从 `~/.codex/skills/` 加载技能：先在 Codex 中查看该技能的实际文件路径，更新现有位置即可；不要同时在新旧位置放置两份同名技能。若要迁移，先备份并移出旧副本，再安装到新位置，最后确认技能只出现一次。

Windows 原生 Codex 与 WSL 内的 Codex 使用各自的用户目录；使用哪个环境，就安装到哪个环境的主目录，不默认两边共享配置。

安装位置依据官方文档：[AGENTS.md 的发现规则](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[本地技能的加载位置](https://learn.chatgpt.com/docs/build-skills)。

### 3. 备份后复制

以下操作用文件管理器即可完成，不需要复制整个 `.codex` 目录。

1. 先查看并备份目标设备上本次要更新的规则文件或技能目录。只安装人设策划时，仅处理同名技能目录；无需安装或覆盖全局规则、圆桌技能。备份放到仓库及技能扫描目录之外，例如在“文稿”或“文档”中建立带日期的备份文件夹。需要保留的本机偏好先合并，不能直接丢弃。
2. 如需安装全局规则，将仓库的 `codex/AGENTS.md` 复制到上表的规则位置；缺少父目录时先创建。目标处保留一个 `AGENTS.md` 文件。
3. 将本次需要的 `skills/yuuu-san-roundtable` 或 `skills/yuuu-san-vtuberPersona` **整个目录**复制到技能父目录下。已有旧技能时，先把旧目录完整移到备份处，再复制新目录，避免旧版本已移除的文件残留。不要只复制 `SKILL.md`，也不要把新目录套在旧目录里面。

圆桌技能的完整结构为：

```text
yuuu-san-roundtable/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── brainstorming.md
    └── cross-review.md
```

人设策划技能的完整结构为：

```text
yuuu-san-vtuberPersona/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── persona-design.md
    ├── language-content.md
    ├── verification.md
    └── test-cases.md
```

`test-cases.md` 是合成测试请求及主持人评审提示，供验证/修订技能时使用；普通人设任务无需读取。独立试用执行者和观众不应收到该题的评审提示。

### 4. 确认生效

安装后新建一个 Codex 会话。技能未出现时重启 Codex，再检查安装位置。

- 如果安装了全局规则，请 Codex“列出当前加载的全局规则来源，确认是否包含初学者沟通偏好”，并核对来源是目标设备上安装的文件。
- 在技能列表中确认能找到本次安装的 `yuuu-san-roundtable` 或 `yuuu-san-vtuberPersona`，并核对实际文件路径。圆桌可用“请用 $yuuu-san-roundtable 比较两个简单方案，完成讨论即可，不修改文件”试用；人设策划可用前面的三个示例之一试用。

圆桌运行需要当前环境提供真实子代理能力；能找到技能不等于该环境能完成多代理讨论。没有该能力时，应明确说明限制，不能把单代理结果称为已完成圆桌。

## 修改本机文件后同步到仓库

日常流程为：**修改本机现用文件 → 验证效果 → 将通用改动同步到仓库 → 审阅差异 → 提交并上传**。本机文件和仓库文件是独立副本，不会自动同步。

### 1. 先更新仓库

在本仓库目录执行：

```sh
git status --short
git pull --ff-only origin main
```

同样先确认工作区没有未处理改动，再执行拉取。多台设备轮流修改时，每次开始同步前都先拉取，减少相互覆盖。

### 2. 同步全局规则的通用改动

用编辑器并排查看本机实际生效的 `AGENTS.md` 和仓库的 `codex/AGENTS.md`，只把需要共享的改动合并到仓库。

**不要直接用本机 `AGENTS.md` 覆盖仓库版本。** 本机文件可能包含个人称呼、本机绝对路径、项目入口和其他仅对当前设备适用的信息。本仓库继续保留初学者沟通偏好，但不加入这些本机内容；项目规则由对应项目维护。

### 3. 同步本次修改的技能

先确认本机正在使用的技能目录，可能位于 `.agents/skills/` 或旧环境的 `.codex/skills/`。

将本机正式文件同步到仓库中对应的 `skills/yuuu-san-roundtable/` 或 `skills/yuuu-san-vtuberPersona/`，包括 `SKILL.md`、`agents/`、`references/` 及实际新增的必要文件。要完整替换时，先将仓库中的旧技能目录移到仓库外备份，再复制本机版本；不要把旧备份、运行日志、临时文件或凭据一起带进仓库。

只同步本次确实修改的技能，不复制整个技能父目录；真实主播材料、测试原始记录和项目专用实现不加入本仓库。只改了规则或只改了一个技能时，仅执行对应部分。

### 4. 审阅、提交、上传

先查看具体差异：

```sh
git status --short
git diff -- codex/AGENTS.md skills/yuuu-san-roundtable/ skills/yuuu-san-vtuberPersona/
```

`git diff` 不显示尚未被 Git 跟踪的新文件内容；`git status` 出现新增文件时，也要打开查看。确认没有个人信息、本机路径、凭据和项目专用内容，再暂存指定范围：

```sh
git add -- skills/yuuu-san-vtuberPersona/
git diff --cached --check
git diff --cached
```

上面以仅同步人设技能为例；同步其他内容时，将 `git add` 的路径替换为本次实际审阅的范围。最后一条会展示本次实际准备提交的全部内容。若修改了 README，另执行 `git add -- README.md`，再检查一次暂存差异。不要使用 `git add .` 将无关文件一起提交。

新设备首次提交前，应在该仓库配置自己的 Git 提交身份；推荐使用 GitHub 账户提供的隐私邮箱，避免将个人邮箱写入提交历史。先将下面两个占位值替换为自己的用户名和 GitHub 隐私邮箱，再执行；`--local` 仅设置当前仓库：

```sh
git config --local user.name "你的 GitHub 用户名"
git config --local user.email "你的 GitHub 隐私邮箱"
```

身份配置完成后提交并上传：

```sh
git commit -m "添加虚拟主播人设策划技能"
git push origin main
git status --short --branch
```

提交说明按实际修改内容填写。上传成功后，工作区应没有未提交改动，分支也不应显示领先或落后。若推送被拒绝，先保存本地提交，获取并合并其他设备的更新、核对冲突后再推送，不执行强制推送。

### 5. 让其他设备使用新版本

在其他设备的仓库目录执行 `git pull --ff-only origin main`，然后按上面的“备份后复制”步骤重新安装。**拉取仓库只更新仓库副本，不会自动更新 Codex 正在使用的文件。** 目标设备若有独有改动，先比较、保留或合并后再安装。

## 收录边界与验证范围

仅收录通用全局规则、圆桌技能、人设策划技能及其必要配置与参考。不迁移账号登录态、API 配置、真实主播资料、聊天记录、个人记忆或其他运行数据。本仓库按技能源码提供手动安装方式，不含自动安装/同步脚本或插件打包。

安装位置已依据上述官方文档核对；尚未在其他设备实际安装验证，Windows 与 WSL 的步骤也尚未在目标环境实测。

人设技能在2026-10-29进行过三类合成任务试用：少话绘画型完整策划、局部口头禅精修、根据负面辨识反馈返修；另有独立主播/观众逐轮文本推演。所试短段能够在无回应时继续，观众回忆了部分具体选择与反应。以上不证明真人声音、实际绘画操作、完整身份识别或长期直播效果。发布整理时核对技能六文件仍与当时受审版本一致，没有为发布改写创作方法。

技能名中的大写 `P` 按原命名保留。本机曾实际发现并启用该名称，但辅助 `quick_validate.py` 的小写命名规则仍会报错；这两种结果分别记录，不能将辅助校验失败推断成所有运行时都拒绝加载。原生 `$` 标记解析、自动选用及其他环境兼容尚未单独实测；安装后请核对目标环境实际行为。
